# ADR-0001：先采用模块化单体

- 状态：已接受
- 日期：2026-08-13

## 背景

LPBot 同时包含 Web、API、任务编排、链索引、签名和合约适配。P00 需要先固定这些责任边界，但目前没有独立扩缩容或故障隔离数据证明每个业务模块都应成为微服务。

## 决策

采用 pnpm/Turborepo TypeScript monorepo。API 先以模块化单体交付，domain 和 API contract 通过 workspace 包形成明确边界；worker、indexer 和 signer 保持独立进程边界。模块之间通过版本化契约、队列事件和数据库所有权协作。只有实际负载、部署或隔离需求成立后，才拆出新的服务。

## 结果

- 单次变更可以原子更新共享契约、实现和测试，降低 P01-P02 初期的分布式协调成本。
- 包边界必须保持单向依赖，不允许以 monorepo 为由跨模块读取内部实现。
- signer 的隔离边界不因模块化单体决策而合并；资金相关权限仍独立部署和审查。
