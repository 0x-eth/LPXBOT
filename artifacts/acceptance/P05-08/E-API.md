# P05-08 E-API

The local residual surface is separate from the existing BSC reader. `GET /api/wallets/helper-residuals?chainId=56` remains read-only. ChainId 31337 adds authenticated latest-snapshot and scan behavior plus `POST /api/wallets/helper-residuals/sweep/preview`, `POST /api/wallets/helper-residuals/sweep`, `GET /api/chain-operation-batches/:batchId`, and the existing `GET /api/chain-operations/:operationId` single-asset view.

Preview accepts exactly `walletId`, `chainId`, `assetIds`, and `snapshotDigest`. Sweep adds only opaque `previewDigest` and `previewToken`; a stable `Idempotency-Key` and reauthentication proof are mandatory. Exact-key parsers reject helper, token, target, selector, calldata, amount, recipient, deadline, fee, feeLimit, serviceFeeBps, duplicate assetId, unknown asset, zero/dust balance, changed or expired snapshot, expired or changed preview, wrong chain, and conflicting idempotency content.

One batch is scoped to one tenant, user, wallet, Helper binding, and snapshot. Each selected unique asset creates one typed `helper-residual-sweep` operation with its own operation ID, nonce, fencing token, semantic/data digest, deadline, and gas cap. Batch GET and operation GET enforce the same tenant/user ownership; another wallet, user, or tenant receives not-found semantics rather than cross-scope data.

`tests/p05-local-helper-sweep-api.test.ts` covers scan/degrade/preview/mixed creation, clock advance without false preview drift, changed/reorged snapshots, allowance/NFT/unknown-token manual recovery, dust and identity failures, provider nonce divergence, a live second batch, and idempotency conflict. `tests/p05-local-helper-sweep-http-api.test.ts` covers authentication, reauthentication, batch and single operation reads, the closed local gate, chainId 56 without an execution route, and invalid runtime composition. Browser requests are independently asserted in `tests/p05-local-helper-sweep-client.test.ts` and the P05-08 E2E suite.
